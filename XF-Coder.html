What this actually does
  • Converts your script to bytes, XORs them with a random key generated fresh each time.
  • Splits the encoded bytes across several randomly-named tables, in a shuffled order.
  • Pads length with an inert comment block and a handful of randomly-named junk tables — never more than a couple dozen top-level variables in total, well inside the 200-local limit Lua/Luau places on a single chunk.
  • At runtime, a small pure-Lua routine rebuilds and XOR-decodes the original text, then runs it with loadstring/load — plain Lua 5.1 syntax, so it runs on any executor or interpreter that supports either.
  • Every run produces different variable names, a different key, and a different byte split — two outputs of the same input never look alike.
Honest limits

This deters casual copying and defeats simple find-and-replace or signature-based "deobfuscators," since there's no fixed pattern to match. It is not unbreakable: because the script must decode itself to run, anyone who hooks loadstring/load at runtime can capture the plain source. That limitation applies to every Lua obfuscator, including paid ones.
